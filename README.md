# หารบิลทริป — Trip Expense Splitter

**เปิดใช้งาน: https://manmenex.github.io/-/**

แอปมือถือ (PWA) สำหรับแบ่งค่าใช้จ่ายกลุ่มในทริป และติดตามว่าใครต้องคืนเงินใครเท่าไร
กรอกรายการเองทั้งหมด ไม่มี AI ไม่มี OCR ไม่อ่านภาพบิล ระบบทำหน้าที่คำนวณ แบ่ง หักลบ และติดตามเท่านั้น

ตอบ 3 คำถามในหน้าเดียว: ทริปนี้ใช้เงินไปเท่าไร / ตอนนี้ใครติดใคร /
**ถ้าจะเคลียร์ให้จบวันนี้ ต้องโอนกี่ครั้ง ครั้งละเท่าไร**

## กฎเรื่องเงิน

จำนวนเงินทุกค่าในระบบเป็น **integer หน่วยสตางค์** เช่น 919.37 บาท = `91937`
แปลงเป็นบาทเฉพาะตอนแสดงผล ไม่มีจุดไหนในโค้ดที่ใช้ floating point กับจำนวนเงิน

- อ่านค่าที่ผู้ใช้กรอกด้วย `parseBaht` ซึ่งทำงานบนสตริง ไม่คูณ 100 บน float
- การหารและการแบ่งตามสัดส่วนทั้งหมดคำนวณบน `BigInt` แล้วแจกเศษด้วยวิธี largest remainder
  ผลรวมจึงตรงกับยอดตั้งต้นเป๊ะเสมอ และผลลัพธ์ deterministic (ตัดเสมอด้วย memberId ที่เรียงแล้ว)

## หลายสกุลเงิน

กรอกบิลเป็นสกุลท้องถิ่นได้ (เยน วอน ดอลลาร์ ฯลฯ) พร้อมอัตราแลกเปลี่ยนของบิลนั้น
ส่วนหนี้สิน แผนโอน และการคืนเงิน คิดเป็นบาทเสมอ จะได้หักลบข้ามบิลต่างสกุลกันได้

- อัตราเก็บเป็นคู่จำนวนเงินจริง (`{ from: 1000, to: 23500 }` = 1,000 เยน = 235.00 บาท)
  ไม่ใช่ทศนิยมลอยๆ คำนวณผ่าน BigInt เหมือนที่อื่น
- สกุลที่ไม่มีหน่วยย่อย (เยน วอน ดอง) เก็บเป็นจำนวนเต็มของสกุลนั้นตรงๆ

### อัตราแลกเปลี่ยนอ้างอิงจาก ธปท.

GitHub Actions ดึงอัตราเฉลี่ยรายวันจาก ธปท. วันละครั้ง แล้ว commit เป็น `public/rates.json`
ติดไปกับแอป เวลากรอกบิลจะมีปุ่มเติมอัตรา "ของวันที่บิล" ให้ในคลิกเดียว

**ทำไมไม่ยิง API ตอนใช้งาน** — แอปเป็นไฟล์ static บน github.io เวลาเรียกข้ามโดเมนไป
bot.or.th เบราว์เซอร์จะติด CORS (มี API key ก็ไม่ช่วย เพราะ CORS ถูกตรวจก่อนถึง key)
และถ้ายิงสดก็จะใช้ตอนไม่มีเน็ตไม่ได้ ซึ่งขัดกับข้อกำหนดของแอปตั้งแต่แรก
การดึงล่วงหน้ายังได้ผลพลอยได้คืออัตราย้อนหลัง จึงใช้อัตราของวันที่บิลได้ ตรงกว่าอัตราวันนี้

ต้องตั้ง repo secret ชื่อ `BOT_API_KEY` (สมัครที่ https://portal.api.bot.or.th)
ถ้าไม่ตั้ง ตารางจะว่างและปุ่มจะไม่โผล่ กรอกอัตราเองได้ตามปกติ

**กับดักของข้อมูลชุดนี้:** ธปท. ประกาศเยนเป็นอัตราต่อ 100 เยน วอนต่อ 1,000 วอน
อ่านพลาดคือเลขผิด 100 เท่าโดยไม่มีอะไรเตือน `scripts/bot-rates.mjs` จึงอ่านจำนวนหน่วย
จากวงเล็บท้ายชื่อสกุล แล้วตรวจซ้ำด้วยช่วงที่เป็นไปได้ของแต่ละสกุล ถ้าหลุดช่วงจะหยุด
ไม่เขียนไฟล์ มี test คุมไว้ที่ `src/lib/__tests__/botRates.test.ts`

**จุดที่ห้ามพลาด:** การแปลงสกุลต้องแปลง *ยอดรวมครั้งเดียว* แล้วกระจายให้แต่ละคน
ตามสัดส่วนยอดในสกุลเดิม ห้ามแปลงทีละคนแล้วเอามาบวกกัน เพราะเศษการปัดของแต่ละคน
จะทำให้ผลรวมไม่เท่ากับยอดบิลที่แปลงแล้ว — มี test คุมไว้ (`currency.test.ts`)

## แชร์ทริปให้เพื่อนดู

ปุ่ม "แชร์ลิงก์" ในหน้าทริปจะบีบอัดข้อมูลทั้งทริปแล้วฝังไว้ใน URL เอง
เพื่อนกดลิงก์แล้วเห็นสรุปได้ทันที ไม่ต้องมี server ไม่ต้องล็อกอิน แก้ไขไม่ได้
และกด "เก็บทริปนี้ไว้ในเครื่องฉัน" เพื่อคัดลอกเข้าเครื่องตัวเองต่อได้

**จุดที่ห้ามพลาดตอนแก้โค้ดส่วนนี้:** การกระจายเศษสตางค์เรียงตาม memberId ที่ sort แล้ว
ตอนย่อ id ให้ลิงก์สั้นลงจึง map ตามลำดับที่ sort แล้วและเติมศูนย์ให้ sort ได้ถูก (m00, m01, ...)
ถ้าลำดับเปลี่ยน เศษ 1 สตางค์จะตกที่คนละคนกับที่เจ้าของทริปเห็น — มี test คุมไว้แล้ว

## Deploy

push ขึ้น branch แล้ว GitHub Actions จะ build และ deploy ขึ้น GitHub Pages ให้เอง
(`.github/workflows/deploy.yml`) โดยจะรัน test กับ typecheck ก่อน ถ้าเลขผิดจะไม่ deploy

**ครั้งแรกต้องเปิด Pages ด้วยมือก่อน** ที่หน้า repo: Settings → Pages → Source เลือก **GitHub Actions**
(GITHUB_TOKEN ของ workflow ไม่มีสิทธิ์สร้าง Pages site ให้เอง) หลังจากนั้น push ทุกครั้ง deploy เองอัตโนมัติ

`base: './'` กับ HashRouter ทำให้แอปทำงานได้ทั้งตอนเปิดจาก subpath
(`/-/` ตามชื่อ repo) และตอนเปิดจากไฟล์ในเครื่อง

## จุดที่ต้องระวังเวลาแก้ต่อ

- `core/` ห้าม import อะไรจาก React หรือ store
- `sum(shares) === statedTotal` และ `sum(payers.amount) === statedTotal` ต้องจริงเสมอ
- ผลรวม balance ของทุกคนต้องเป็น 0 — `assertBalanced` จะ throw ใน dev/test ถ้าไม่เป็น
  (production ให้ log แทน ดู `setStrictInvariants`)
- ส่วนต่างระหว่างยอดรายคนกับยอดบนบิลเกิน 5 สตางค์ **ห้ามปัดกลบอัตโนมัติ**
  ต้องบล็อกการบันทึกจนผู้ใช้แก้เองหรือกดยอมรับส่วนต่าง
- การชำระเงินทุกครั้งสร้าง record ใหม่ ห้ามแก้ทับของเดิม และห้ามลบตอนแก้บิล
