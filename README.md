# หารบิลทริป — Trip Expense Splitter

**เปิดใช้งาน: https://manmenex.github.io/-/**

แอปมือถือ (PWA) สำหรับแบ่งค่าใช้จ่ายกลุ่มในทริป และติดตามว่าใครต้องคืนเงินใครเท่าไร
กรอกรายการเองทั้งหมด ไม่มี AI ไม่มี OCR ไม่อ่านภาพบิล ระบบทำหน้าที่คำนวณ แบ่ง หักลบ และติดตามเท่านั้น

ตอบ 3 คำถามในหน้าเดียว: ทริปนี้ใช้เงินไปเท่าไร / ตอนนี้ใครติดใคร /
**ถ้าจะเคลียร์ให้จบวันนี้ ต้องโอนกี่ครั้ง ครั้งละเท่าไร**

## กฎเรื่องเงิน

จำนวนเงินทุกค่าในระบบเป็น **integer หน่วยสตางค์** เช่น 919.37 บาท = `91937`
แปลงเป็นบาทเฉพาะตอนแสดงผล ไม่มีจุดไหนในโค้ดที่ใช้ floating point กับจำนวนเงิน

- อ่านค่าที่ผู้ใช้กรอกด้วย `parseBaht` ซึ่งทำงานบนสตริง ไม่คูณ 100 บน float
- การหารและการแบ่งตามสัดส่วนทั้งหมดคำนวณบน `BigInt` แล้วแจกเศษด้วยวิธี largest remainder
  ผลรวมจึงตรงกับยอดตั้งต้นเป๊ะเสมอ และผลลัพธ์ deterministic (ตัดเสมอด้วย memberId ที่เรียงแล้ว)

## หลายสกุลเงิน

กรอกบิลเป็นสกุลท้องถิ่นได้ (เยน วอน ดอลลาร์ ฯลฯ) พร้อมอัตราแลกเปลี่ยนของบิลนั้น
ส่วนหนี้สิน แผนโอน และการคืนเงิน คิดเป็นบาทเสมอ จะได้หักลบข้ามบิลต่างสกุลกันได้

- อัตราเก็บเป็นคู่จำนวนเงินจริง (`{ from: 1000, to: 23500 }` = 1,000 เยน = 235.00 บาท)
  ไม่ใช่ทศนิยมลอยๆ คำนวณผ่าน BigInt เหมือนที่อื่น
- สกุลที่ไม่มีหน่วยย่อย (เยน วอน ดอง) เก็บเป็นจำนวนเต็มของสกุลนั้นตรงๆ

สกุลเงินและอัตราถูกจำไว้ที่ **ทริป** (`Trip.defaultCurrency` และ `Trip.rates`)
บิลใหม่หยิบไปใช้เป็นค่าตั้งต้น และเวลาแก้ในบิลก็จำกลับไปที่ทริปด้วย
ไปญี่ปุ่นทั้งทริปจึงไม่ต้องเลือกเยนกับกรอกอัตราใหม่ทุกบิล ปิดแอปเปิดใหม่ก็ยังอยู่
เก็บอัตราแยกตามสกุล ทริปเดียวไปหลายประเทศได้

เครื่องคิดอัตราแลกเปลี่ยนมีสองทาง ใช้คอมโพเนนต์ `RateConverter` ร่วมกัน
ต่างกันแค่ว่าอัตราถูกเก็บไว้ที่ไหน

| หน้า | เก็บที่ | ใช้ตอน |
|---|---|---|
| `/rate` | ระดับแอป (`quickRate`) | เช็กเร็วจากหน้าแรก ไม่ผูกกับทริป |
| `/trip/:id/rate` | ที่ทริป (`Trip.rates`) | ตั้งอัตราที่บิลใหม่จะหยิบไปใช้ |

ทั้งสองพิมพ์ฝั่งไหนก็ได้อีกฝั่งคิดให้ พร้อมตารางเทียบจำนวนกลมๆ ไว้กวาดตาตอนยืนดูป้ายราคา
หน้าแรกมีแถบอัตราอยู่บนสุด โชว์เลขไว้เลยจึงมักไม่ต้องกดเข้าไปด้วยซ้ำ
ใช้อัตราที่ตั้งเองก่อน (เป็นเรตที่โดนจริง) ไม่มีค่อยตกไปใช้ของ ธปท.

### อัตราแลกเปลี่ยนอ้างอิงจาก ธปท.

GitHub Actions ดึงอัตราเฉลี่ยรายวันจาก ธปท. วันละครั้ง แล้ว commit เป็น `public/rates.json`
ติดไปกับแอป เวลากรอกบิลจะมีปุ่มเติมอัตรา "ของวันที่บิล" ให้ในคลิกเดียว

**ทำไมไม่ยิง API ตอนใช้งาน** — แอปเป็นไฟล์ static บน github.io เวลาเรียกข้ามโดเมนไป
bot.or.th เบราว์เซอร์จะติด CORS (มี API key ก็ไม่ช่วย เพราะ CORS ถูกตรวจก่อนถึง key)
และถ้ายิงสดก็จะใช้ตอนไม่มีเน็ตไม่ได้ ซึ่งขัดกับข้อกำหนดของแอปตั้งแต่แรก
การดึงล่วงหน้ายังได้ผลพลอยได้คืออัตราย้อนหลัง จึงใช้อัตราของวันที่บิลได้ ตรงกว่าอัตราวันนี้

ต้องตั้ง repo secret ชื่อ `BOT_API_KEY` (สมัครที่ https://portal.api.bot.or.th)
ถ้าไม่ตั้ง ตารางจะว่างและปุ่มจะไม่โผล่ กรอกอัตราเองได้ตามปกติ

ใช้ `mid_rate` (อัตรากลาง) เป็นค่าตั้งต้น กรอกเรตที่โดนจริงทับได้เสมอ

ไฟล์อัตราถูก commit โดย `github-actions[bot]` ซึ่ง GitHub **จงใจไม่ trigger workflow**
จาก push ที่ใช้ `GITHUB_TOKEN` (กันลูปไม่รู้จบ) `deploy.yml` จึงต้องมี trigger `workflow_run`
ดักตอน workflow อัตราทำงานจบ ไม่งั้นไฟล์จะอยู่ใน repo แต่ไม่เคยขึ้นเว็บ

ธปท. จำกัด **31 วันต่อคำขอ** สคริปต์จึงซอยช่วงให้เอง และเก็บสะสมลงไฟล์เดิม
รันประจำวันจึงใช้แค่คำขอเดียว (ดึงเฉพาะช่วงล่าสุดแล้ว merge)
เก็บย้อนหลัง 90 วัน (`BOT_DAYS_BACK`) — ไฟล์ราว 19 KB, gzip 1 KB, รันครั้งแรก 3 คำขอ
ไม่ต้องเก็บยาวกว่านี้เพราะทริปจำอัตราของตัวเองไว้แล้ว ตารางนี้ใช้ตอนตั้งบิลแรกของทริปเป็นหลัก

**กับดักของข้อมูลชุดนี้:** ธปท. ประกาศบางสกุลเป็นอัตราต่อหลายหน่วย โดยเขียนไว้ใน
ชื่อสกุลแบบนี้ `"JAPAN : YEN (100 YEN) (JPY)"` และ `"INDONESIA : RUPIAH (1,000 RUPIAH) (IDR)"`
— มีทั้งคำต่อท้ายตัวเลข มีคอมมา และมีวงเล็บรหัสสกุลตามมาอีกชั้น
อ่านพลาดคือเลขผิด 100 เท่าโดยไม่มีอะไรเตือน

`scripts/bot-rates.mjs` จึงมองหาเฉพาะวงเล็บที่ขึ้นต้นด้วยตัวเลข แล้วตรวจซ้ำด้วยช่วง
ที่เป็นไปได้ของแต่ละสกุล ถ้าหลุดช่วงจะหยุดและพิมพ์ข้อมูลดิบออกมา ไม่เขียนไฟล์
test ที่ `src/lib/__tests__/botRates.test.ts` ใช้ response จริงจาก ธปท. เป็น fixture

**จุดที่ห้ามพลาด:** การแปลงสกุลต้องแปลง *ยอดรวมครั้งเดียว* แล้วกระจายให้แต่ละคน
ตามสัดส่วนยอดในสกุลเดิม ห้ามแปลงทีละคนแล้วเอามาบวกกัน เพราะเศษการปัดของแต่ละคน
จะทำให้ผลรวมไม่เท่ากับยอดบิลที่แปลงแล้ว — มี test คุมไว้ (`currency.test.ts`)

## แชร์ทริปให้เพื่อนดู

ปุ่ม "แชร์ลิงก์" ในหน้าทริปจะบีบอัดข้อมูลทั้งทริปแล้วฝังไว้ใน URL เอง
เพื่อนกดลิงก์แล้วเห็นสรุปได้ทันที ไม่ต้องมี server ไม่ต้องล็อกอิน แก้ไขไม่ได้
และกด "เก็บทริปนี้ไว้ในเครื่องฉัน" เพื่อคัดลอกเข้าเครื่องตัวเองต่อได้

**จุดที่ห้ามพลาดตอนแก้โค้ดส่วนนี้:** การกระจายเศษสตางค์เรียงตาม memberId ที่ sort แล้ว
ตอนย่อ id ให้ลิงก์สั้นลงจึง map ตามลำดับที่ sort แล้วและเติมศูนย์ให้ sort ได้ถูก (m00, m01, ...)
ถ้าลำดับเปลี่ยน เศษ 1 สตางค์จะตกที่คนละคนกับที่เจ้าของทริปเห็น — มี test คุมไว้แล้ว

## Deploy

push ขึ้น **main** แล้ว GitHub Actions จะ build และ deploy ขึ้น GitHub Pages ให้เอง
(`.github/workflows/deploy.yml`) โดยจะรัน test กับ typecheck ก่อน ถ้าเลขผิดจะไม่ deploy

**ครั้งแรกต้องเปิด Pages ด้วยมือก่อน** ที่หน้า repo: Settings → Pages → Source เลือก **GitHub Actions**
(GITHUB_TOKEN ของ workflow ไม่มีสิทธิ์สร้าง Pages site ให้เอง) หลังจากนั้น push ทุกครั้ง deploy เองอัตโนมัติ

deploy รันจาก `main` เท่านั้น — environment `github-pages` ล็อกไว้ให้ deploy ได้จาก
default branch อยู่แล้ว ถ้าปล่อยให้ branch อื่นรันด้วย นอกจากจะ fail ทุกครั้ง
ยังไปแย่ง concurrency group จน run ของ main โดนยกเลิกทิ้ง

`base: './'` กับ HashRouter ทำให้แอปทำงานได้ทั้งตอนเปิดจาก subpath
(`/-/` ตามชื่อ repo) และตอนเปิดจากไฟล์ในเครื่อง

## สแกนบิลและสลิป

ใช้ [`tesseract.js`](https://github.com/naptha/tesseract.js) v7 (Tesseract คอมไพล์เป็น WebAssembly)
รันบนเครื่องผู้ใช้ทั้งหมด ไม่มีเซิร์ฟเวอร์ ไม่มี API key รูปไม่ออกจากเครื่อง ใช้ได้ตอนออฟไลน์

ไฟล์เอนจินกับโมเดลภาษา (รวม ~15 MB) ก๊อปจาก `node_modules` ตอน build ด้วย
`scripts/copy-ocr-assets.mjs` ไม่ commit เข้า repo และไม่เอาเข้า precache ของ PWA
คนที่ไม่กดปุ่มสแกนจะไม่โดนโหลดเลย

สองโหมดใน `lib/ocr.ts`:
- `amount` — อังกฤษตัวเดียว จำกัดให้อ่านเฉพาะตัวเลข ใช้กับยอดบนสลิป
- `receipt` — ไทย+อังกฤษ ขอผลแบบมีตำแหน่งคำ (`blocks`) ใช้แกะรายการในใบเสร็จ

tesseract ให้แค่ "ตัวอักษรอะไร อยู่พิกัดไหน" ส่วนที่แปลงเป็นรายการอยู่ใน `lib/receipt.ts`
ซึ่งเป็นฟังก์ชันบริสุทธิ์ทั้งหมด เทสด้วยผลที่ OCR อ่านใบจริงออกมา
(`__tests__/fixtures/vet-receipt.json` เก็บไว้ทั้งดุ้นรวมขยะ ไม่ได้คัดออก)

หลักการ: **ทุกอย่างที่ OCR อ่านมาเป็นข้อเสนอ ผู้ใช้ต้องกดยืนยันก่อนเสมอ**
และถ้ารายการบวกกันแล้วไม่ตรงกับยอดบนใบเสร็จ (`reconciled === false`)
ห้ามติ๊กให้ล่วงหน้าสักอัน — หลักเดียวกับที่บิลบล็อกการบันทึกเมื่อยอดไม่ตรง
ข้อนี้ยังกันเคสจุดทศนิยมหายด้วย เพราะยอดจะไม่มีทางตรง

### ไอเดียที่ยังไม่ทำ: ปุ่ม "อ่านให้แม่นขึ้น"

เพดานของ tesseract คือมันไม่เข้าใจบริบท เห็น "สูตร" เบลอๆ ก็เดาเป็น "สูดร" ตามรูปร่าง
ยอดเงินมักรอด แต่ชื่อสินค้าเพี้ยน หาข้อมูลตัวเลือกไว้แล้ว (ก.ย. 2026):

| | รันที่ไหน | API key | รูปออกนอกเครื่อง | ออฟไลน์ | แม่นกับใบเสร็จไทย |
|---|---|---|---|---|---|
| tesseract.js (ใช้อยู่) | เบราว์เซอร์ | ไม่ต้อง | ไม่ | ได้ | พอใช้ |
| EasyOCR / PaddleOCR | เซิร์ฟเวอร์ Python | ไม่ต้อง | ไปเซิร์ฟเวอร์ตัวเอง | ไม่ได้ | ดีกว่าชัดเจน |
| zerox + vision model | เซิร์ฟเวอร์ Node/Python | ต้องมี | ไป OpenAI/Google | ไม่ได้ | ดีที่สุด |

ถ้าจะทำ ให้ทำเป็นปุ่มเสริมที่ยิงไปเซิร์ฟเวอร์เฉพาะตอนออนไลน์และเฉพาะตอนที่กด
เก็บ tesseract ไว้เป็นค่าตั้งต้น เพราะจังหวะที่ใช้แอปนี้จริงคือนั่งอยู่ร้านต่างประเทศ
เน็ตไม่ดี ตอนนั้นเซิร์ฟเวอร์ช่วยอะไรไม่ได้ และถ้าเลือกทางเซิร์ฟเวอร์
EasyOCR/PaddleOCR เหมาะกว่า zerox เพราะไม่ต้องมี key และรูปไม่ต้องไปอยู่ในมือบริษัทอื่น

### ครอบตัดรูป — วัดแล้วไม่ช่วยกับใบเสร็จปกติ

มีให้ลากกรอบเลือกส่วนของรูปก่อนอ่าน (ค่าตั้งต้นคือทั้งรูป) แต่วัดกับใบกำกับภาษีจริงแล้ว:

```
ทั้งรูป             5 รายการ ยอดถูกหมด ยอดรวมถูก
ครอบเฉพาะตาราง       5 รายการ ยอดถูก แต่ไม่มีแถวยอดรวมให้ตรวจสอบ
ครอบตาราง+ยอดรวม     4 รายการ หายไปหนึ่ง และมีขยะเข้ามาแทน
```

tesseract ใช้ทั้งหน้าจับตำแหน่งคอลัมน์ ตัดให้แคบลงกลับทำให้มันมีข้อมูลน้อยลง
ครอบตัดจึงมีไว้สำหรับกรณีอื่น เช่น มีของอย่างอื่นติดมาในรูป หรือใบเสร็จสองใบในรูปเดียว

## เลขเวอร์ชัน

`major.minor` มาจาก `package.json` ส่วนเลขท้ายคือจำนวน commit นับอัตโนมัติตอน build
(`vite.config.ts` -> `appVersion()`) โชว์อยู่ในหน้าตั้งค่า

เลขท้ายเพิ่มเองทุกครั้งที่ commit ไม่ต้องจำว่าต้องบวกเอง และเทียบกันได้ทันที
ว่าเครื่องไหนเก่ากว่ากัน ซึ่งเป็นคำถามที่ถามบ่อยสุดเวลา deploy แล้วสงสัยว่าขึ้นหรือยัง

**deploy workflow ต้องมี `fetch-depth: 0`** ไม่งั้น `actions/checkout` clone มาแบบตื้น
นับ commit ได้ 1 ทุกครั้ง เลขเวอร์ชันจะค้างที่ `x.y.1`

## การอัปเดตแอป (`lib/appUpdate.ts`)

`registerType: 'autoUpdate'` + สั่ง `skipWaiting` และ `clientsClaim` เองใน `vite.config.ts`
**ต้องสั่งทั้งคู่** ค่าที่ plugin ใส่ให้เองมีแต่ `skipWaiting` ผลคือ SW ตัวใหม่ทำงานแล้ว
แต่ไม่เข้าควบคุมหน้าที่เปิดค้างอยู่ หน้านั้นจึงกินไฟล์เก่าจากแคชต่อไปเรื่อยๆ

มีสามทางให้ได้เวอร์ชันใหม่ เรียงจากอัตโนมัติสุดไปแรงสุด ทดสอบครบทั้งสามแล้ว:

1. **กลับเข้าแอป** — `visibilitychange`/`focus` สั่ง `registration.update()` เจอแล้วรีโหลดเอง
2. **ปุ่ม "อัปเดตเดี๋ยวนี้"** — โผล่เองเมื่อตรวจเจอตัวใหม่ติดตั้งเสร็จ (`onUpdateReady`)
   มีไว้เพราะการรีโหลดอัตโนมัติพึ่งไม่ได้ทุกเบราว์เซอร์ ผู้ใช้ iOS Safari เจอว่า
   กดตรวจแล้วก็ยังเป็นเวอร์ชันเดิม และทำซ้ำบน Chromium ไม่ได้ การกดปุ่มแล้ว reload
   เองทำงานได้ทุกที่ ไม่ต้องเดา
3. **"บังคับโหลดใหม่"** — ล้าง Cache Storage + ถอน service worker แล้วโหลดใหม่
   **ห้ามแตะ IndexedDB** ทริป บิล และรูปอยู่ตรงนั้นทั้งหมด มีเทสยืนยันว่าข้อมูลอยู่ครบ

## จุดที่ต้องระวังเวลาแก้ต่อ

- `core/` ห้าม import อะไรจาก React หรือ store
- `sum(shares) === statedTotal` และ `sum(payers.amount) === statedTotal` ต้องจริงเสมอ
- ผลรวม balance ของทุกคนต้องเป็น 0 — `assertBalanced` จะ throw ใน dev/test ถ้าไม่เป็น
  (production ให้ log แทน ดู `setStrictInvariants`)
- ส่วนต่างระหว่างยอดรายคนกับยอดบนบิลเกิน 5 สตางค์ **ห้ามปัดกลบอัตโนมัติ**
  ต้องบล็อกการบันทึกจนผู้ใช้แก้เองหรือกดยอมรับส่วนต่าง
- การชำระเงินทุกครั้งสร้าง record ใหม่ ห้ามแก้ทับของเดิม และห้ามลบตอนแก้บิล
